# API голосования для разработчиков бэкенда

Для варианта без бэкенда на `cowork.ru` используйте прямое подключение к
Google Таблице по инструкции в [VOTING_GOOGLE_SHEET.md](VOTING_GOOGLE_SHEET.md).
Ниже описан альтернативный API для отдельного сервера.

Страницы участников: `/vote/question-1/` … `/vote/question-4/`.
Сценические страницы с итогами: `/vote/question-1/results/` … `/vote/question-4/results/`.
Общий отчёт: `/vote/results/`.

По умолчанию фронтенд обращается напрямую к опубликованному Apps Script.
Чтобы вместо него использовать отдельный API, при сборке задайте пустую
`NEXT_PUBLIC_VOTING_APPS_SCRIPT_URL` и адрес
`NEXT_PUBLIC_VOTING_API_BASE_URL` (например, `/api/voting` или полный HTTPS URL).
Если обе переменные пусты, работает локальный демонстрационный режим на
`localStorage`: голоса с разных устройств в нём не объединяются. Переменная
с адресом API публичная — в ней не должно быть ключа доступа.

## Эндпоинты

`GET {BASE}/snapshot` — состояние для участника. Ответ:

```json
{
  "ownAnswers": { "question-1": "yes" },
  "results": {
    "questions": {
      "question-1": { "yes": 12, "no": 8 },
      "question-2": { "yes": 0, "no": 0 },
      "question-3": { "yes": 0, "no": 0 },
      "question-4": { "yes": 0, "no": 0 }
    },
    "updatedAt": "2026-11-12T09:00:00.000Z"
  }
}
```

`POST {BASE}/votes` — записать один ответ. Тело:

```json
{ "questionId": "question-1", "answer": "yes" }
```

Успешный ответ — тот же объект, что у `GET /snapshot`, уже с сохранённым
голосом. Повторное голосование по тому же вопросу должно возвращать HTTP 409
и не менять запись.

`GET {BASE}/results` — общие итоги для экрана сцены и общего отчёта. Ответ —
объект `results` из примера выше, без `ownAnswers`. Для каждого вопроса нужны
целые неотрицательные `yes` и `no`. Поле `updatedAt` может быть строкой ISO 8601
или `null`. Фронтенд сам вычисляет общее число ответов как сумму счётчиков.

## Правила хранения и доступа

- Идентифицировать участника на сервере через защищённую сессию или персональный
  код. Публичный `localStorage` ID не подтверждает личность участника.
- Сделать запись неизменяемой и обеспечить уникальность пары
  `(participant_id, question_id)` в БД. Проверка только в интерфейсе не защищает
  от повторного запроса.
- Не отдавать персональные идентификаторы в `GET /results`; там нужны только
  агрегированные счётчики.
- Ответы API не кэшировать. Сценическая страница запрашивает результаты каждые
  5 секунд, общий отчёт — каждые 10 секунд.
- Запросы фронтенда используют `credentials: include`. При другом домене API
  потребуется корректная настройка CORS и cookie.
