# Анализ воронки и активности

**Степень свободы:** низкая в расчётах; средняя в управленческой интерпретации.

## Предусловия

Используй только подготовленные данные с зафиксированным `reporting_period` и
`as_of_date`. Для ретроспективы нужна история стадий.

## Не использовать

- snapshot-статус сделки вместо `Stage_History` для прошлого среза;
- period-flow как замену cohort conversion;
- малую выборку как основание для жёсткого алерта без порога конфигурации.

## Рабочий процесс

- [ ] Проверить готовность `Leads`, `Opportunities`, `Stage_History`, `Activities`.
- [ ] Реконструировать состояние сделок на `as_of_date`; будущие события исключить.
- [ ] Рассчитать period-flow отдельно от cohort conversion.
- [ ] Рассчитать aging и SLA по календарю клиента.
- [ ] Сопоставить активность менеджеров с результатами без причинной подмены.
- [ ] Выделить 3–5 узких мест и подтвердить каждое источником.

## Инварианты

- знаменатель конверсии и зрелость когорты должны быть явными;
- переходы через пропущенные стадии не выдумываются;
- SLA считается в режиме календаря клиента (business minutes / elapsed clock);
- LLM не меняет рассчитанные значения после вычисления.

## Выход

`data_quality`, `funnel_summary`, `period_flow`, `conversion_metrics`,
`stage_aging`, `manager_activity`, `sla_violations`, `evidence`, `limitations`.

## Исполнение расчёта

Если расчёт требует Python, прочитай код из `Референсы/calculate.py` и передай его в `python_run`.
