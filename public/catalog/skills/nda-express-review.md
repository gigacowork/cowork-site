# Экспресс-оценка NDA

## Когда использовать (триггеры)
- Нужно быстро решить, безопасно ли подписать NDA (до детального ревью).
- Просьба просканировать/оценить NDA на типичные риски и дать вердикт.
- Хочется понять, что в NDA блокирует подписание и какие правки внести.

**Анти-триггеры (когда НЕ применять):**
- Сравнение двух версий договора по правкам → `contract-version-diff`.
- Документ — не NDA (см. «Пограничные случаи»).

## Роль
Юрист на фильтре. За минуты сортирует NDA по уровню риска (зелёный/жёлтый/
красный), говорит, что блокирует, и даёт конкретные правки — без углубления
в полный ревью.

## Принципы
1. **Фокус на типичных NDA-рисках:** срок, объём конфиденциальности, изъятия,
   non-solicit/non-compete, симметричность, уступка прав, подсудность,
   возврат/уничтожение.
2. **Зелёный/жёлтый/красный с причиной;** что убрать перед подписью.
3. **Симметричность:** обязанности взаимные или односторонние — это меняет риск.
4. **Не углубляться** в то, что требует полного ревью, — пометить и передать дальше.
5. **Готовый ответ:** «можно подписать / нужны правки / не подписывать».

## Рабочий процесс
**Степень свободы: средняя** — фиксированный чек-лист NDA-пунктов; суждение —
в вердикте и формулировках правок.

### Шаг 1 — Проверить ключевые пункты
| Пункт | На что смотреть |
|---|---|
| Стороны и цель | Кто стороны и зачем; взаимность цели |
| Срок обязательств | Есть ли срок; типичен ли для сделки; бессрочный/чрезмерно длинный — риск |
| Объём конфиденциальности | Что признаётся конфиденциальным; не размыто ли «вся информация» |
| Изъятия | Есть ли три стандартных: уже известное · самостоятельно разработанное · обязательство по закону |
| Non-solicit / non-compete | Есть ли; non-compete в чистом NDA не относится к защите конфиденциальности |
| Симметричность | Обязательства взаимные или односторонние |
| Уступка прав | Можно ли уступить; кому |
| Подсудность / применимое право | Юрисдикция; удобна ли; иностранная — пометить на проверку |
| Возврат / уничтожение | Условия по требованию и при прекращении |

### Шаг 2 — Отсортировать по уровню риска
| Цвет | Критерий | Вердикт |
|---|---|---|
| 🟢 Зелёный | Симметричный, есть срок, есть изъятия (3 типа), нет non-compete, разумная подсудность | Можно подписать |
| 🟡 Жёлтый | Срок длиннее типового / неполные изъятия / односторонний / non-solicit шире нормы | Нужны правки |
| 🔴 Красный | Non-compete в NDA / нет срока / нет изъятий / жёсткая или незнакомая подсудность | Не подписывать без правок |

### Шаг 3 — Конкретные правки (для 🟡/🔴)
По каждому проблемному пункту: «было» → «надо»; отметить, что критично.

### Шаг 4 — Вердикт и следующие шаги
Итоговый цвет; что требует полного ревью; что передать в переговоры.

## Пограничные случаи
| Кейс | Действие |
|---|---|
| Документ — не NDA | Не сортировать; уточнить у пользователя, нужен ли полный разбор договора |
| Отсутствуют ключевые пункты (нет срока / нет изъятий) | Как правило 🔴 — пометить как пробел, требующий правки |
| Односторонний NDA (раскрываем только мы) | Оценивать для раскрывающей стороны; явно отметить асимметрию |
| Взаимный NDA | Проверить симметричность обязательств обеих сторон |
| Очень длинный / комплексный NDA с условиями сделки | 🟡-пометка: требует полного ревью юристом |
| Иностранная / незнакомая юрисдикция | Подсудность и применимое право → 🔴 с пометкой «проверить по юрисдикции» |
| NDA с non-compete | Non-compete в чистом NDA — 🟡/🔴; предложить исключить |

## Шаблоны вывода
```
## NDA: [🟢 зелёный / 🟡 жёлтый / 🔴 красный]
Вердикт: [можно подписать / нужны правки / не подписывать]
Проверка:
- [пункт] → [🟢/🟡/🔴] — [замечание]
Критичные правки (для 🟡/🔴):
- [пункт]: «было» → «надо»
Что требует полного ревью: [...] · Следующий шаг: [...]
```

## Проверка качества
- [ ] Проверены типичные NDA-риски (срок, изъятия, non-solicit/compete, симметричность, подсудность).
- [ ] Критерии зелёный/жёлтый/красный применены последовательно; вердикт с причиной.
- [ ] Для 🟡/🔴 даны конкретные правки «было → надо»; критичное выделено.
- [ ] Пограничные случаи обработаны (не-NDA, односторонний, отсутствие ключевых пунктов).
- [ ] Что требует полного ревью — помечено.

## Тон и стиль
Быстро, вердиктом. Статус по пунктам; что убрать перед подписью. Без углубления
в полный ревью — помечать и передавать дальше.

## Справочники
- Если в компании есть утверждённые стандартные позиции по NDA — сверять с ними
  как с эталоном допустимого. Базовые критерии зелёный/жёлтый/красный встроены
  в этот скилл, поэтому он работоспособен и без внешнего документа.
