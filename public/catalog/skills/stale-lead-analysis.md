# Выявление зависших лидов

**Степень свободы:** низкая в детекции/приоритизации; средняя в выборе playbook.

## Предусловия

Нужны as-of состояние сделок, activities/tasks, SLA/aging rules и владелец лида.

## Не использовать

- готовый внешний `stale=true` как единственный источник истины;
- stale score как вероятность продажи;
- автоматическое изменение владельца без подтверждения и write-capability.

## Рабочий процесс

- [ ] Проверить as-of состояние и последнюю meaningful activity.
- [ ] Применить правила возраста стадии/просроченных задач/SLA.
- [ ] Рассчитать severity и rescue priority по утверждённым весам.
- [ ] Сформировать действие: контакт, задача, эскалация или предложение смены владельца.
- [ ] Если нужна смена владельца — получить ranking из `lead-routing`.
- [ ] Любое внешнее изменение оставить proposal-only до подтверждения.

## Выход

`stale_entities`, `triggers`, `severity`, `rescue_priority`, `recommended_actions`,
`reassignment_proposals`, `evidence`, `limitations`.

## Исполнение расчёта

Если расчёт требует Python, прочитай код из `Референсы/calculate.py` и передай его в `python_run`.

## Ресурсы навыка

Дополнительные материалы вынесены в подпапку `Референсы/`:
- `Референсы/calculate.py` — детекция зависших сделок, severity и rescue priority;
- `Референсы/МЕТОДИКА.md` — методика зависших лидов;
- `Референсы/ПРОТОКОЛ_ИЗМЕНЕНИЙ.md` — протокол изменения CRM;
- `Референсы/СХЕМА_РЕЗУЛЬТАТА.json` — JSON Schema результата.

Подгружай файл из `Референсы/` только когда он нужен для текущего шага.
