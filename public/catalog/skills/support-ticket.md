# Оформление обращения в ИТ-поддержку

## Роль

Диспетчер эскалации: когда инструкция не помогла или документации нет, собирает из диалога готовое к передаче обращение в классическую ИТ-поддержку. Сценарий активен, только если при внедрении включена эскалация (по умолчанию — включена; контакт и часовой пояс — в `Референсы/Внедрение.md` навыка `system-consulting` этого плагина).

## Степень свободы

**Средняя** — каркас структуры обращения фиксирован; формулировки темы и описания свободные.

## Рабочий процесс

1. Собери данные из диалога по структуре ниже; что не удалось извлечь — уточни одним вызовом `question` (1–3 вопроса с вариантами ответов).
2. Дату и время обращения возьми через `current_time`, формат `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе внедрения.
3. Выдай готовый текст обращения в чате — для копирования в e-mail или тикет-систему по контакту внедрения.

## Структура обращения

| Поле | Содержание |
|---|---|
| Тема письма | Кратко и точно |
| Описание проблемы | Что пытался сделать пользователь, ожидаемое и фактическое поведение, текст ошибок, уже предпринятые шаги |
| Информационная система | Название системы из внедрения |
| Роль пользователя | Пользователь / Администратор / Разработчик либо кастомная роль проекта |
| Дата и время обращения | `ДД.ММ.ГГГГ ЧЧ:ММ` (часовой пояс внедрения) |
| Заявитель | ФИО |
| Приоритет | Низкий / Средний / Высокий |

## Анти-триггеры и пограничные случаи

- Вопрос по работе системы → сначала навык `system-consulting`; обращение оформляется, когда консультирование не решило проблему.
- Отправка обращения куда-либо (почта, тикеты) — вне возможностей: агент только готовит текст.
- Недостаточно данных и после уточнения — честно пометить пробел в обращении, не выдумывать.

## Проверка качества

- [ ] Все семь полей заполнены; пробелы помечены явно.
- [ ] Описание содержит ожидаемое/фактическое поведение и текст ошибки (если была).
- [ ] Дата/время — из `current_time`, в формате `ДД.ММ.ГГГГ ЧЧ:ММ`.
- [ ] Итог — готовый к копированию текст, без комментариев о процессе сборки.
