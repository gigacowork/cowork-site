# Как вести работу над проектом

Записка для новой сессии Claude. `README.md` описывает, что за проект и как он
устроен внутри; здесь — про всё вокруг: что лежит в рабочей папке, откуда
берутся исходники, как правка доезжает до репозитория и какие грабли в
окружении уже известны.

Ориентиры по содержанию: структура адресов — `ПРОЕКТ_COWORK_RU.md`, состав
страниц и текстов — `BRIEF.md`, недостающие ассеты — `ASSETS-TODO.md`.

---

## 1. Постоянные требования заказчика

1. **Правки уезжают в папку проекта сразу.** Не «покажу файл, скопируешь сам»,
   а доставить в `cowork-site` на машине и убедиться, что доехало.
2. **Адреса страниц сверяются с `ПРОЕКТ_COWORK_RU.md`.** Новые маршруты берутся
   оттуда, а не придумываются.
3. Язык общения и комментариев в коде — русский.

### «Сценарии Роли» — как устроено

По папке на роль: `HR и кадры`, `Бухгалтерия`, `Закупки`, `ИТ-поддержка`,
`Продажи`, `Управленческие решения`, `Финансы`, `Юристы`. Внутри роли:

- `<Заголовок сценария>.webp` — кадр для карточки блока «Какие задачи…»;
- `<Заголовок шага>.mp4` — запись экрана для блока «Решения»;
- `<Имя>.screenstudio/` — проекты записи, **на сайт не идут**;
- у «Управленческих решений» дополнительно `README.md` и папки агентов с

**Имя файла совпадает с заголовком на странице** — по нему и сопоставляется.
Заголовки иногда переименовывают вместе с текстом карточки: так «Делегируйте
подготовку писем и КП» превратилась в «Превращайте встречу в план действий», и
видео пришлось перевешивать на другой шаг. Если имя не совпадает ни с одним
заголовком — сначала уточнить, а не угадывать.

В корне «Сценарии Роли» ещё лежат `ВИЗУАЛЬНЫЙ СТИЛЬ ДАШБОРДОВ.md` и два
`ОБРАЗЕЦ ДАШБОРДА (*).html` — это правила оформления для агентов внутри
GigaCowork, к сайту не относятся.

## 3. Цикл одной правки

```
правка → npm run build → проверка в браузере → доставка в проект → сверка md5
```

Сборка обязательна даже для правки текста: экспорт статический, и ошибка типа
или несуществующий путь вылезают только на `next build`.

```bash
cd /home/claude/cowork-site
npm run build > /tmp/build.log 2>&1; echo "exit=$?"
```

Логи в файл, а не в `head`: при пайпе сборка иногда падает по SIGPIPE и код
возврата врёт.

Проверка — на собранном `out/`, не на dev-сервере:

```bash
cd out && (nohup python3 -m http.server 3311 > /tmp/srv.log 2>&1 &)
```

`pkill -f http.server` убивает саму оболочку — сервер поднимать отдельным
вызовом через `nohup … &`.

Замеры и скриншоты — Playwright с готовым Chromium:

```js
chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })
```

Скрипты класть в `/home/claude/`, а не в `/tmp`: из `/tmp` не резолвится модуль
`playwright`. Перед замером геометрии — `html{scroll-behavior:auto!important}`,
иначе плавная прокрутка сбивает координаты.

Кодек H.264 в этом Chromium отсутствует: видео на странице не проигрывается, но
разметка, постеры и размеры проверяются нормально. Внешние хосты недоступны.

### Доставка и сверка

Корень проекта на машине:

## 4. Выкладка в репозиторий — не наша зона

Релизами в git занимается **отдельный агент**. Эта сессия правит только
мастер-папку `cowork-site` и в репозиторий не лезет: не запускает выкладку, не
трогает `~/Documents/GitHub/cowork-site`, не делает коммитов и пушей. Если
кажется, что правку надо «выложить» — это к нему.

Знать про цепочку всё равно нужно, потому что от неё зависит, куда класть файлы.

**Как устроено.** В корне «Верстка сайта 2.0» лежит `release-to-github.command`.
Двойной клик — и он гонит `rsync -a --delete` из мастер-папки в
`~/Documents/GitHub/cowork-site`, отбрасывая `.git/`, `node_modules/`, `.next/`,
`out/`, `.vercel/`, `.DS_Store`, `tsconfig.tsbuildinfo`, `next-env.d.ts`,
`*.log`, `.env*` и сам скрипт. Дальше изменения видит GitHub Desktop, коммит и
пуш в `main` делает человек или агент.

Пуш в `main` запускает `.github/workflows/deploy.yml`: Node 22, `npm ci`,
`npm run build` с `NEXT_PUBLIC_BASE_PATH=/<имя-репозитория>` и публикация папки
`out/` на GitHub Pages. Сайт отдаётся по адресу
`https://<логин>.github.io/<имя-репозитория>/`, поэтому `basePath` = имя репо;
берётся из контекста Actions, чтобы переименование репозитория не сломало пути.

**Что из этого следует для правок.**

1. Класть всё в мастер-папку. В `~/Documents/GitHub/cowork-site` править
   бессмысленно: `--delete` снесёт при следующей выкладке.
2. Файлы, нужные репозиторию, тоже живут в мастер-папке и едут вместе со
   всем остальным — `.github/workflows/deploy.yml`, `.gitignore`,
   `.gitattributes`. Их нельзя заводить только на стороне GitHub: `--delete`
   их удалит.
3. Ничего не завязывать на абсолютные пути: на Pages сайт лежит в подпапке.
   Все ссылки и ассеты идут через `basePath`/`assetPrefix` из
   `next.config.ts` — руками `/img/...` в HTML не писать, только через `Image`,
   `Link` и обычные относительные пути, которые Next сам префиксует.
4. Проверять сборку локально обычным `npm run build` (без `NEXT_PUBLIC_BASE_PATH`)
   можно и нужно, но помнить: на Pages пути будут с префиксом. Если правка
   касается ссылок или ассетов, стоит прогнать сборку и с переменной:
   `NEXT_PUBLIC_BASE_PATH=/cowork-site npm run build`.

**Мастер-папка шире, чем кажется.** В ней есть то, чего нет в моей рабочей
копии в контейнере: `.github/`, `.gitattributes`, `SCREENSHOTS-ceo.md` и папка
`platform-whatsnew/` (заготовка страниц «Что нового» и `/platform`, ещё не
влитая в `src`). Перед правками, которые задевают структуру, лучше сверить
верхний уровень мастер-папки, а не полагаться на свою копию.

## 5. Особенности окружения

**Две одинаковые по имени точки монтирования.** В `~/mnt` лежат два входа
«Верстка сайта 2.0» — NFC и NFD-нормализация одного имени. Один из них пустой.
Никогда не собирать путь строкой; выбирать каталог перебором:

```python
base = os.path.expanduser("~/mnt")
for d in os.listdir(base):
    p = os.path.join(base, d)
    if os.path.isdir(p) and "cowork-site" in os.listdir(p):
        root = p; break
```

По той же причине имена файлов в исходниках сопоставляются по вхождению
подстроки после `unicodedata.normalize("NFC", …)`, а не сравнением целиком.
В именах попадаются неразрывные пробелы («Агент подбора и\xa0оценки…»), лишние
пробелы перед расширением и двоеточия вместо слэшей («use_cases:accounting»).

**Удалять `device_bash` не умеет** (`Operation not permitted`). Ненужное
переносится в `_to_delete/`, дальше — руками.

**Для ffmpeg и PIL кириллические пути ненадёжны.** Перед обработкой файлы
копируются во временную папку под ASCII-именами.

## 7. Ассеты: как готовятся

### Видео в блоке «Решения»

Исходники — `Сценарии Роли/<Роль>/<Заголовок шага>.mp4`, приходят 1940×1080
(иногда 1872×1080) при 60 к/с и весе 5–20 МБ.

```bash
ffmpeg -y -i in.mp4 -an -vf "scale=1176:-2,fps=30" \
  -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 26 -preset slow \
  -movflags +faststart out.mp4
ffmpeg -y -i out.mp4 -frames:v 1 -c:v libwebp -quality 82 poster.webp
```

1176 — двойная ширина карточки (588). Постер — **первый** кадр: иначе при
нажатии «play» видно скачок. Вес падает в 5–14 раз.

Раскладка: `public/video/<slug>-<шаг>.mp4`,
постер `public/img/use-cases/<slug>-<шаг>-poster.webp`, поля `video`,
`videoPoster`, `videoRatio` у шага в `src/lib/use-cases.ts`. `videoRatio` —
пропорция **сжатого** файла (`1176/654` или `1176/678`): карточка кадрируется
ровно по ней, без полей.

Шаги роли HR собираются шаблоном `commonSteps` — тексты общие, видео своё,
передаётся вторым аргументом по индексу шага.

### Кадры сценариев (превью в `ScenarioStack`)

Исходники — `Сценарии Роли/<Роль>/<Заголовок сценария>.webp`, 1336×960. Внутри:
карточка 1176×800 со смещением (80, 56) и запечённая вокруг мягкая тень.

Тень надо снимать: её вешает сам компонент фильтром, иначе теней две, а
остатки полупрозрачных тёмных пикселей за скруглением дают грязные углы.
Порогом по альфе не обойтись — остаток доходит до 20 и оставляет ступеньку на
дуге. Правильно — пересобрать альфу маской:

1. обрезать `(80, 56, 1256, 856)`;
2. «растянуть» цвет карточки на ~6 px наружу, чтобы тень не проступала на
   полупрозрачной кромке;
3. подставить альфу скруглённого прямоугольника, **радиус 48**, со сглаживанием
   через суперсэмплинг ×4;
4. обнулить RGB там, где альфа 0.

Эталон — кадры бухгалтерии (`accounting-*.webp`): они приехали чистым
экспортом, по ним и сверялся радиус. Готовый профиль альфы по краю:
`0 → 64 → 112 → 128 → 191 → 223 → 255`, без полок.

Пути и alt — `src/lib/scenario-previews.ts`, порядок совпадает с порядком
сценариев роли в `use-cases.ts`.

## 8. Типографика текстов

- Неразрывный пробел после коротких предлогов и союзов: `на `, `и `,
  `с `, `по `, `для `, `за `, `от `, `из `.
- `\n` в заголовке — жёсткий перенос из макета. Компонент `Lines` превращает его
  в `<br>` от `md` и снимает ниже: на 390 разбивка, рассчитанная на десктоп,
  рвала бы строки не в тех местах.
- Точка в конце коротких подписей и заголовков карточек не ставится; внутри
  многопредложенного абзаца — обычная пунктуация.

**Осторожно с инструментом Edit** на строках, где есть литералы ` `: он
регулярно не находит совпадение. Надёжнее — точечная замена скриптом на Python
с `assert s.count(old) == 1`.

## 10. Открытые хвосты

- `/docs` — не решено, как закрывать от индексации: весь раздел через
  `robots.txt`, только старые версии с canonical на актуальную, или `noindex` на
  каждой странице.
- Обрамление доков (`scripts/docs-chrome/header.html` и `footer.html`) отстало от
  живых `Header`/`Footer` — ждёт решения, пересобирать ли.
- `uploadDate: "2026-08-14"` в разметке `VideoObject` обучающих видео — догадка,
  нужна настоящая дата публикации.
- `public/img/platform/hero-preview.png` и `public/img/icons/pentagon.svg` больше
  нигде не используются.
- Пункты колонки «Платформа» в подвале, помеченные `hidden: true`, ждут своих
  страниц — адреса им проставлять из `ПРОЕКТ_COWORK_RU.md`.
- SEO-описание страницы HR (`src/content/seo.ts`) перечисляет «составление
  вакансий и онбординг», которых в блоке сценариев больше нет.
